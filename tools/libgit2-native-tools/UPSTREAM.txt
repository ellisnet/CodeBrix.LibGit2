================================================================================
tools/libgit2-native-tools - WHERE EVERY VENDORED TREE CAME FROM
================================================================================

This folder vendors two upstream source trees and one set of upstream build
files. None of them is ever edited. Nothing in any build script here clones,
downloads or otherwise fetches source at build time - see README.txt for the
rule this exists to satisfy. This file records, for each tree, its identity,
its licence, exactly how the copy was made, and how to check it again.

This file sits BESIDE the trees rather than inside them, so libgit2/ and
mbedtls/ contain upstream's files and nothing else.

How the copy was made, 2026-10-17 (the one-time vendoring step; the only
network use besides the Mbed TLS clone and the one nuget.org download below):

    git clone https://github.com/libgit2/libgit2.git \
        ~/ClaudeHome/libgit2-upstream-scratch/libgit2
    git -C ~/ClaudeHome/libgit2-upstream-scratch/libgit2 \
        checkout 5853918c4c6a7b12f8becf4bd11ff4362ebb9020
    rsync -a --exclude=/.git \
        ~/ClaudeHome/libgit2-upstream-scratch/libgit2/ \
        tools/libgit2-native-tools/libgit2/

Afterwards `diff -r -q -x .git <clone> tools/libgit2-native-tools/libgit2`
reported no differences.

Tree checksum (run from inside libgit2/; symlinks hashed through their
target):

    find . \( -type f -o -type l \) | LC_ALL=C sort \
        | xargs -d '\n' sha256sum | sha256sum

    3845e8e3bde38d9882ba4001aea8314fd9baa5fb28e7a4184c6490b0b3fce58c  -

The same command in the upstream clone (with `-path ./.git -prune`) gave the
same value.

NOTHING IN THE BUILD FETCHES. libgit2's CMake has one download path,
deps/chromium-zlib/CMakeLists.txt (FetchContent of Chromium's zlib), and it is
reached only with -DUSE_BUNDLED_ZLIB=Chromium. Every build here uses
USE_BUNDLED_ZLIB=ON (= deps/zlib) on Linux, Android and macOS, and on Windows
upstream's own default (no system zlib -> deps/zlib), so that code is never
configured. The Linux and Android builds prove it on every run by building
with no network interface.

upstream's own .gitignore files (./.gitignore, tests/resources/.gitignore and
six inside the tests/resources fixtures) are part of the
snapshot. For this commit `git ls-files -ci --exclude-standard` lists NOTHING:
no file upstream tracks is hidden by them, so a plain `git add` of this folder
picks up the whole tree (../.gitignore re-includes what the repository-root
.gitignore would otherwise hide - see its comment).

Submodule      : framework/ = https://github.com/Mbed-TLS/mbedtls-framework
                 at dde0c4a0e448a0552f18817dcea633bb851fd288 (2026-06-24), the

Licence        : Apache-2.0 OR GPL-2.0-or-later (dual; LICENSE in this tree,

                 Android binaries as LICENSE-MbedTls.txt.
Used by        : the two Android builds ONLY (android/build.py), compiled first
                 as STATIC libraries (libmbedtls.a, libmbedx509.a,
                 libmbedcrypto.a) and linked into libgit2-5853918.so. The
                 Linux builds use OpenSSL at run time, Windows Schannel, macOS

                 ssl_debug_helpers_generated.c, psa_crypto_driver_wrappers*.
                 ...), so the build runs with GEN_FILES=OFF and needs no

3rdparty/      : everest and p256-m are compiled as separate static libraries

                 MBEDTLS_PSA_P256M_DRIVER_ENABLED are commented out in
                 include/mbedtls/mbedtls_config.h, which is used unmodified),
                 are not linked, and android/verify.py records that none of
                 their symbols is in the library.

NOT MODIFIED
================================================================================
No file in libgit2/, mbedtls/ or reference-upstream/ has been modified,
renamed, reformatted or deleted, and none ever should be. There is no patch
mechanism in this folder: if a build ever needed a change to upstream source,
the rule is to stop and decide, not to patch quietly. (The two first-run
problems of 2026-10-17 - the image's pcre-devel and the NDK headers' `inline`
under libgit2's strict C90 - were both solved with build options; see
BUILD-PROVENANCE.txt.)

VERIFYING A SNAPSHOT AGAINST UPSTREAM (optional, needs network)
--------------------------------------------------------------------------------
    git clone https://github.com/libgit2/libgit2.git /tmp/lg2-verify
    git -C /tmp/lg2-verify checkout 5853918c4c6a7b12f8becf4bd11ff4362ebb9020
    diff -r -x .git /tmp/lg2-verify libgit2          # expect no differences

    git clone --branch v3.6.7 \
        https://github.com/Mbed-TLS/mbedtls.git /tmp/mb-verify
    git -C /tmp/mb-verify submodule update --init
    diff -r -x .git /tmp/mb-verify mbedtls           # expect no differences

That check is a convenience for a human, not a build step.
